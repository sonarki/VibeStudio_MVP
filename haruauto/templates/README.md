# 뼈대 (templates)

24시간 납기를 가능하게 하는 장치입니다. **백지에서 시작하지 않기 위한 것**입니다.
고객 요청이 들어오면 가장 가까운 뼈대를 고르고, 고객 데이터에 맞게 `config.yaml`만
채운 뒤 필요한 부분만 손봅니다.

## 설치

```bash
pip install -r requirements.txt
```

## 공통 규약

모든 뼈대는 `common/runner.py`를 통해 아래를 자동으로 갖습니다.

| 기능 | 의미 |
|---|---|
| `config.yaml` 한 곳 설정 | 고객이 코드를 열지 않고 값을 바꿀 수 있다 |
| `--dry-run` | 실제 반영 없이 결과를 미리 본다 |
| `logs/run.log` | 무슨 일이 있었는지 남는다 |
| 실패 시 메일 알림 | 조용히 멈추는 자동화를 막는다 |
| 행 단위 건너뛰기 | 나쁜 입력 한 줄이 전체를 멈추지 않는다 |
| 원본 미변경 | 결과를 새로 만든다. 되돌릴 수 있다 |

## 목록

### `sheet_pipeline` — 파일 취합·정제 (LITE)
여러 엑셀/CSV를 하나로 합치고 정제해 결과 파일을 만듭니다.

커버하는 요청: *"매일 채널별로 받은 주문서를 하나로 합쳐서 정리해요"*

지원: 공백 제거 · 열 이름 변경 · 필수 열 검증 · 빈 행 제외 · 금액 문자열
(`₩`, 쉼표) 숫자 변환 · 날짜 통일 · 중복 제거 · 정렬 · 요약 시트

```bash
cd sheet_pipeline
cp config.example.yaml config.yaml   # 값 채우기
python run.py --dry-run
python run.py
```

### `doc_factory` — 문서 대량 생성 (LITE)
데이터 한 행당 문서 한 장을 만듭니다.

커버하는 요청: *"거래처마다 정산서를 매달 손으로 만들어요"*

지원: `{{항목명}}` 치환 · 금액/날짜 서식 · 파일명 동적 생성 · 파일명 안전화
(`/ \ : * ? " < > |` 제거) · 기존 파일 덮어쓰기 보호

```bash
cd doc_factory
cp config.example.yaml config.yaml
python run.py --dry-run
python run.py
```

## 아직 뼈대가 없는 것 (SPRINT 요청 시 그때 제작)

- `api_sync` — 외부 서비스 API → 정규화 → 시트/DB 적재 + 알림
- `scheduled_job` — 위 작업을 정해진 시각에 자동 실행

두 개는 고객사가 쓰는 서비스에 따라 형태가 크게 달라져서 미리 만들어두는 효용이 낮습니다.
다만 `common/runner.py`는 그대로 재사용하므로, 설정·로그·알림·예외 처리는 이미 끝나 있는
상태에서 연동 로직만 새로 씁니다.

## 실제 확인된 동작

`sheet_pipeline`, `doc_factory` 모두 지저분한 샘플 데이터로 실행을 확인했습니다.

- `sheet_pipeline`: 2개 파일 6행 입력 → 빈 주문번호 1행 제외, 중복 1행 제거,
  `"무료"` 같은 비숫자 값 1건 건너뛰고 기록, 최종 4행 + 요약 시트 생성
- `doc_factory`: 3행 입력 → 문서 3건 생성, 파일명의 `/`·`*` 자동 치환,
  재실행 시 기존 3건 전부 덮어쓰기 보호로 건너뜀
