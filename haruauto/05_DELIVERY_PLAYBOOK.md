# 24시간 납품 실행 매뉴얼

> 환불 보장은 이 문서가 지켜냅니다. **24시간은 야근으로 만드는 게 아니라 범위 통제와
> 사전 제작된 뼈대로 만듭니다.** 매번 백지에서 시작하면 24시간은 불가능합니다.

---

## 1. 시간 배분 (결제 완료 = T+0)

| 구간 | 작업 | 담당 |
|---|---|---|
| **T+0 ~ T+1h** | 접근 권한 수령, 샘플 데이터 확보, 뼈대 선택 | 캡틴 → Claude |
| **T+1 ~ T+8h** | 핵심 로직 구현 + 실데이터 1회전 통과 | Claude |
| **T+8 ~ T+12h** | 예외 처리, 실패 시 알림, 로그 | Claude |
| **T+12 ~ T+16h** | 담당자용 실행 인터페이스 (버튼/시트 메뉴/스케줄) | Claude |
| **T+16 ~ T+20h** | 가이드 문서 + 조작 영상 + 인수인계 자료 | Claude |
| **T+20 ~ T+24h** | **버퍼.** 인수인계 세션 진행 | 캡틴 |

**T+20 이후는 새 기능을 넣지 않습니다.** 버퍼를 먹으면 납기가 죽습니다.

---

## 2. 수주 전 필수 판정 (진단 통화 중 실시간)

아래 중 **하나라도 YES면 24시간 수주 금지**:

- [ ] 공인인증서·OTP·캡차가 필수인 시스템에 접근해야 한다
- [ ] 대상 서비스 약관이 자동 접근을 금지한다
- [ ] 고객사 내부망에만 있고 외부에서 접근 불가하다
- [ ] 고객사 IT팀 승인이 필요하고 그게 24시간 안에 안 난다
- [ ] 자동화 대상 업무가 사실상 3개 이상이다
- [ ] 고객이 "일단 만들어보고 맞춰가죠"라고 말한다 (= 범위 미확정)
- [ ] 결과가 법적 효력을 갖는 문서다 (세금계산서 발행 등 사람 확인 필수)

아래는 **모두 YES여야 수주**:

- [ ] 입력이 무엇이고 출력이 무엇인지 한 문장으로 말할 수 있다
- [ ] 샘플 데이터를 지금 받을 수 있다
- [ ] "성공"의 정의가 명확하다 (= 무엇이 나오면 끝인지)
- [ ] 담당자 연락이 24시간 내내 가능하다

---

## 3. 뼈대 카탈로그 (`templates/` 참조)

24시간을 만드는 진짜 장치입니다. **백지에서 시작하지 않습니다.**

| 뼈대 | 커버하는 요청 | 등급 |
|---|---|---|
| `sheet_pipeline` | 여러 파일/시트 취합 → 정제 → 결과 시트 생성 | LITE |
| `doc_factory` | 데이터 행 → 문서 대량 생성 (견적서·정산서·보고서) | LITE |
| `api_sync` | 외부 서비스 API → 정규화 → 시트/DB 적재 + 알림 | SPRINT |
| `scheduled_job` | 위 항목을 정해진 시각에 자동 실행 + 실패 알림 | SPRINT |

모든 뼈대 공통 내장:
- 설정을 코드가 아닌 `config.yaml` 한 곳에 모음 (고객이 직접 수정 가능)
- 실행 로그 파일 자동 기록
- 실패 시 지정 메일/메신저로 알림
- `--dry-run` 모드 (실제 반영 없이 결과만 확인)

---

## 4. 품질 하한선 (이거 미달이면 납품 아님)

1. **실제 고객 데이터로 최소 1회 완주**했다. 샘플만 돌아간 건 납품 아님.
2. **틀린 입력이 들어와도 죽지 않는다.** 빈 셀, 형식 오류, 중복 행 → 건너뛰고 로그 남김.
3. **담당자가 코드를 안 열고 실행할 수 있다.** 버튼, 시트 메뉴, 또는 더블클릭 파일.
4. **실패를 사람이 안다.** 조용히 멈추는 자동화는 수작업보다 위험합니다.
5. **되돌릴 수 있다.** 원본을 덮어쓰지 않고 결과를 별도로 만듭니다.

---

## 5. 인수인계 패키지 (4종 세트)

1. **사용 가이드 문서** (A4 2장 이내)
   - 실행 방법 3단계 / 결과 확인 위치 / 문제 생겼을 때 확인할 것 3가지 / 연락처
2. **조작 영상** (3~5분, 화면 녹화 + 음성)
3. **소스와 설정 일체** (고객사 소유. 압축본 + 저장 위치 안내)
4. **인수인계 세션 30분** — 담당자가 **직접 한 번 실행하는 것까지** 보고 끝냅니다

---

## 6. 실패 시 프로토콜 (지켜야 브랜드가 삽니다)

**T+16h 시점에 완주가 불투명하면, 그 즉시 고객에게 전화합니다.**

> "지금 상황 그대로 말씀드립니다. [사유]로 24시간 안에 완주가 어려울 것 같습니다.
> 두 가지 중에 고르실 수 있습니다.
> 하나, 지금 전액 환불해 드립니다. 오늘 안에 처리됩니다.
> 둘, [축소된 범위]까지는 확실히 드릴 수 있습니다. 그걸로 받으시고 차액을 환불받으실 수도 있습니다.
> 어느 쪽이든 대표님이 손해 보시는 일은 없게 하겠습니다."

- T+24h가 지나서 통보하는 건 **금지**. 늦은 정직은 정직이 아닙니다.
- 환불은 **당일 처리**. 미루면 그때부터 분쟁입니다.
- 환불하고도 만들던 것까지는 그냥 드립니다. 돈은 못 벌어도 평판은 지킵니다.

## 7. 동시 수주 상한

| 동시 진행 | 판단 |
|---|---|
| 1건 | 안전 |
| 2건 | **상한.** 목표(₩980만) 달성선 |
| 3건 이상 | **금지.** 하나 무너지면 전부 무너짐 |

3번째 문의가 오면 거절하지 말고 **일정을 미룹니다**:
> "지금 진행 중인 건이 있어서, 내일 [시각]부터 착수하는 조건이면 가능합니다."

## 8. 첫 건 이후 (24시간 이후의 이야기)

첫 납품이 성공하면 즉시 확보할 것:
- [ ] **서면 후기** (실명·회사명 사용 동의 포함) ← 여기서부터 사회적 증거가 진짜가 됩니다
- [ ] **절감 시간 실측치** (전 3시간 → 후 5분 같은 구체 수치)
- [ ] **추가 자동화 대상 2개** 청취 (같은 고객의 두 번째 건이 가장 쉬운 매출입니다)
- [ ] **소개 요청** — "비슷한 일로 고생하시는 대표님 한 분만 소개해 주실 수 있을까요?"

**후기 1건이 생기는 순간 랜딩페이지의 정직 고지 블록을 후기 블록으로 교체합니다.**
그때가 진짜 시작입니다.
